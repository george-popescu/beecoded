# Help

Use `nectar guide --json` for the installed command and skill catalog. Answer the
user's question with the relevant capability and its boundary; do not load every
skill or turn a help request into implementation, installation or a release.
Resolve invocation names from the current host rather than assuming Codex and
Claude share the same command syntax. If the CLI is unavailable, consult the
packaged README and report that availability was not verified.

Distinguish ordinary change Review, whole-project Audit, cross-artifact Burciu
Inspection and focused Test Review. Build implements an authorized outcome; Honey
coordinates delivery. Capture saves an idea, while `nectar debt [path] [--json]`
inspects recorded limitations. None authorizes a publish merely by being selected.

`nectar board [path]` displays a snapshot of recorded project state. For optional
usage collection, inspect `nectar telemetry --help` and explain the supported
sources before enabling anything or importing history. Unknown usage is not zero;
API-priced estimates are not bills, and activity is not proof of quality or delivery.
Do not install hooks, enable collection or disclose session data from a help request.

Give the smallest relevant next action. Do not promise host features, telemetry
coverage or live state that the available tools cannot establish.
