# Honey

Own the requested result using the [workflow contract](../../references/workflow.md).
Resolve consequential uncertainty, choose a fitted approach and keep a proportional
plan. Use the [plan format](../../references/plan-format.md) only for persisted work.
Continue under existing implementation authority until the outcome is delivered.

Shape, Plan and Build describe responsibilities you may handle in one session.
Delegate coherent independent work when it helps. Give workers the outcome,
relevant context and ownership; collect actual changes and reusable evidence.

Own the final review; Build does not perform a duplicate review when you coordinate
it. Match depth to risk, reuse current checks and assess affected areas after
repairs. Use [Security](../nectar-security/SKILL.md) when requested or a sensitive
change warrants focused assessment, not as a universal delivery gate.

Use the workflow's completion and stopping rules. Respect explicit user limits;
continue only while a concrete defect or missing evidence justifies more work.

Resume from current artifacts and source without restarting the workflow. Report
the delivered outcome, verification and real limitations. Follow existing commit
or release authorization; accepted work can use Close for recoverable archiving.
